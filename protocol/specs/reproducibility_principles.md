# Reproducibility & Verification Principles

本文件描述 nebula-freeze 协议在设计时遵循的可复现与可验证原则，便于审计 / 合规 / 第三方工程团队理解整个证据链的定位。

---

## 1. 独立复现，而不是「相信作者」

- 假设第三方对策略作者没有任何信任；
- 通过 FREEZE-A / FREEZE-B 提供：
  - 明确的五指纹；
  - 完整的文件清单与哈希；
  - 可选的时间戳与签名；
- 第三方只要在 **自己的环境** 中获得同一套输入（代码 + 数据 + spec + seed），即可复现同样的结果。

---

## 2. 零信任验证（Zero-Trust Verification）

- 协议层的目标不是让别人「相信」谁，而是让别人：
  - 通过 hash / OTS / 签名等手段，自主判断文件是否被篡改；
  - 通过 schema 和 SPEC 文档，自主判断字段是否齐全、类型是否正确；
  - 通过 five_fingerprint，自主判断当前结果对应的是哪一套环境与口径。

---

## 3. 最小披露（Minimal Disclosure）

- 协议鼓励 **只暴露必要信息**：
  - 对策略逻辑、参数搜索过程等敏感内容，可以完全不公开；
  - 只需公开「可验证的外壳」：
    - 指纹；
    - 结构；
    - 统计结果；
    - 时间戳与证据。

- FREEZE-A / FREEZE-B 的 schema 和 SPEC 均只定义结构与语义，不强制暴露策略内部细节。

---

## 4. 可组合、可演进

- 通过 `proto_version` 控制协议演进；
- 通过 JSON Schema 控制结构；
- 通过五指纹控制「世界线」；
- 上述三者组合，允许：
  - 在不破坏历史 artefact 的前提下增量升级；
  - 对同一五指纹下的多个结果包进行横向比较。

---

## 5. 与审计流程的关系

- 对机构内部来说：
  - FREEZE-A 可以作为「入库 artefact」；
  - FREEZE-B 可以作为「审核 artefact」；
  - 合规部门可以在不理解所有业务细节的情况下，先检查结构与证据链是否完备。

- 对外部审计 / 合作方来说：
  - 只要拿到 FREEZE-A/B 包和协议说明，即可在本地独立执行验证工具；
  - 协议层不绑定任何特定实现（撮合引擎 / 执行引擎等），只约束外部可见的「壳」。
